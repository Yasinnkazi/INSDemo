Why is this login secure?

The SQL query uses parameterized queries (also called prepared statements):

cursor.execute(
    "SELECT * FROM users WHERE username=? AND password=?",
    (username, password)
)

How does this prevent SQL Injection?

1. Separation of Code and Data

The SQL structure is defined first with ? placeholders. User input is sent separately as data, so it can never be interpreted as SQL code.

2. Automatic Escaping

The database driver automatically escapes special characters like ', ", --, and /*. Even if an attacker enters malicious SQL, it's treated as plain text.

3. Query Compilation

Parameterized queries are compiled once and executed multiple times. The query plan is fixed before user input is bound, making injection impossible.

Try It Yourself

Go to the Insecure Login page and enter ' OR '1'='1 as both username and password. It will bypass login. Then come back here and try the same payload - it will fail because the secure system treats it as literal text.

Insecure vs Secure - Query Difference

❌ Insecure (String Concatenation)
f"...WHERE username='{user}' AND password='{pw}'"

User input becomes part of SQL code

✔ Secure (Parameterized Query)
"...WHERE username=? AND password=?"

User input stays as data only
