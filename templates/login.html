Why is this login vulnerable?

The SQL query is built using string concatenation:

query = f"SELECT * FROM users \
WHERE username='{username}' \
AND password='{password}'"

Example Attack

If you enter admin' -- as username and anything as password, the query becomes:

SELECT * FROM users \
WHERE username='admin' --' AND password='anything'

The -- is SQL's comment syntax. Everything after it is ignored, so the password check is completely bypassed!

Another Example

Using ' OR '1'='1 makes the WHERE clause always true:

SELECT * FROM users \
WHERE username='' OR '1'='1' AND password='' OR '1'='1'

This returns ALL users from the database, and the first user (usually admin) is used for login.

⚠ Security Risk

String concatenation in SQL queries allows attackers to modify the query structure by injecting SQL keywords and syntax. Never use this in production!
